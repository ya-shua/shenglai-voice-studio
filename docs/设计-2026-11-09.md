## 一、改造背景与页面新结构

**旧页面的问题**：「我的音色」堆着素材区、方式一、方式二、进阶等大块，试听散在卡片和素材区多处，顶栏还留着一个能切音色的下拉——入口东丢西落，违背"每个目标全站只有一个入口"。

**重构目标**：页面只做两件事——**管理音色**、**直接试听**。新结构自上而下：

```
我的音色
├─ 音色库（卡片网格）
│   每张卡：当前音色徽标行 + 头像/名字/✏️ + [应用 …… 删除]
├─ 语音参数长条（全宽）
│   语速  音调  音量  格式 ……………… 恢复默认
└─ 下半区（左右等大、同高）
    ├─ 左：试听音色（语气 + 试听按钮 / 文本框 / 常显播放器）
    └─ 右：试听记录（超 50 条滚动，点条目回放，导出）
```

## 二、信息架构铁律的落地

延续 1.2.0 确立的铁律，这一轮把残留的多入口收干净：

1. **顶栏当前音色：`<select>` → 不可交互 `<span id="cur-voice" class="cur-voice-display">`**，删除其 change 事件。顶栏只做状态展示。
2. **切换主音色唯一入口 = 音色卡「应用」按钮**（`POST /api/voices/current`）。
3. **「应用」按钮智能分流**：
   - 卡片处于改名态（存在 `.rename-input`）→ 走改名保存；空值/同名 → 点「取消」退出
   - 常态 → 设为当前音色；已是当前则提示，不重复请求

## 三、音色卡片设计

### 3.1 结构与对齐

```
.voicecard
├─ .vhead（纵向）
│   ├─ .vbadge-row（固定 min-height:20px）  ← 当前音色放徽标，否则留空占位
│   └─ .vrow：头像 + 名字 + ✏️
└─ .actions：应用（左，primary）  删除（右，space-between）
```

**关键：`.vbadge-row` 固定高度占位。** 曾经当前音色的徽标独占一行、把头像名字往下挤，非当前卡片没这行，两张卡片头像错位、高度不一。改为无论是否当前都保留同高的徽标行后，所有卡片头像顶部对齐、卡片同高（实测两卡 avatarTop 一致、cardH 一致）。

### 3.2 内联改名（不撑高卡片）

- 点 ✏️，输入框出现在头像旁边（名字位置），不再独占一行撑高卡片；标题区只留一个「取消」（`.rename-cancel`），回车或点外面的「应用」保存。
- 坑：选择器 `.vtitle .mini` 会误选隐藏铅笔，取消按钮必须用明确的 `.rename-cancel`。

### 3.3 改名后端：reference_path 同步修复（`lib/library.py`）

`rename_voice` 会重命名素材目录，但注册表的 `reference_path` 仍指向旧目录、改名后参考音频失效。修复：重命名素材目录后，若 `reference_path` 解析后位于旧目录内，用 `Path.relative_to` 改写到新目录下对应路径；空值/异常兜底，不阻断改名。

## 四、语音参数：百分比整数与双向输入

### 4.1 后端契约（不能违背）

| 参数 | 语义 | 范围 | 默认 |
|---|---|---|---|
| `rate` | 语速**倍数**（float，1.0=正常） | 0.5 ~ 2.0，硬校验超出报 ProviderError | 1.0 |
| `pitch` | 音调**倍数**（float，1.0=正常） | 0.5 ~ 2.0，硬校验 | 1.0 |
| `volume` | 音量绝对值（int） | 0 ~ 100 | 50 |

### 4.2 为什么不能直接用 0–100 整数

1. **会直接报错、合成不了**：rate/pitch 是倍数，直接传 80 会被当成 80 倍速，超出 2.0 硬范围。
2. **100 封顶就无法调快/调高**：若把 100 映射成 1.0，只能往慢、往低调，加速/升调能力被废掉。

### 4.3 方案：百分比整数展示层

- 语速、音调前端用**百分比整数**：`100 = 正常 1.0`，范围 **50–200**（对应 0.5–2.0），提交时 `rate = 输入值 / 100`。
- 音量本就是 0–100 整数，直接传。
- 每个控件 = 滑块 + 可输入 `number` 框，**双向联动**：拖滑块更新数字框、数字框输入同步滑块；输入越 min/max 自动夹取（clamp）。
- 全整数、无小数点，同时保留双向调节。

转换式：`rate = 输入整数 / 100`；整数范围 = 后端 min×100 ~ max×100。

## 五、参数持久化与试听记录（新模块 `lib/mine.py`）

### 5.1 职责与存储

| 文件（数据根目录） | 内容 |
|---|---|
| `mine_settings.json` | 语速/音调/音量/格式（百分比整数） |
| `audition_history.json` | 试听记录数组，每条含 time/text/emotion/rate/pitch/volume/format/file/url |

### 5.2 参数持久化

- 控件改动 → **防抖 400ms** 后 `POST /api/mine/settings` 落盘，避免拖动滑块时频繁写文件。
- 进入页面 `GET /api/mine/settings` 回填；字段缺失/非法回退默认并夹取。
- **恢复默认**：长条右侧按钮 → `POST /api/mine/reset`，回到 100/100/50/wav 并回填。

### 5.3 试听记录：50 封顶 + 实体文件联动

- **50 条封顶**：新记录 insert 到最前，超出的被挤掉。
- **截断连带删音频**：被挤掉的记录，其 `outputs` 对应文件一并删除，不留孤儿文件（这正是过去 outputs 静默累积的根因）。
- **路径安全**：删文件前把目标 resolve 并确认位于 `outputs` 目录内，防路径穿越。
- 记录框与试听框**左右等大、同高**；记录区固定高度、超出 `overflow-y:auto` 滚动。
- 点条目 → 播放器回放；「导出」按钮 → `<a download>` 下载该音频原文件，可自选保存位置。

### 5.4 接口一览

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/mine/settings` | 读持久化参数 |
| POST | `/api/mine/settings` | 保存（合并、钳制） |
| POST | `/api/mine/reset` | 恢复默认 |
| GET | `/api/mine/history` | 读试听记录 |
| POST | `/api/mine/history` | 追加记录（50 封顶、挤出删文件） |

**空间澄清**：记录文件本身是几 KB 文本、封顶 50 条，几乎不占空间；真正占磁盘的是 `outputs` 音频，且属磁盘占用而非内存，不影响运行。导入无实际场景，不做；导出靠单条下载 + 直接访问 outputs 文件夹覆盖。

## 六、网络瞬时错误重试（`lib/providers/base.py`）

`http_send` 底层对**瞬时网络错误**自动重试，所有供应商共用：

- 捕获 `URLError / TimeoutError / ConnectionError`，重试 **2 次**（最多 3 次请求），间隔 1.5s 递增（1.5s、3.0s）。
- `HTTPError`（业务错误码）**不重试**，直接带响应体报错。
- 起因：百炼注册时 `[Errno 10054] 连接被重置`，属瞬时问题而非配置错误。

## 七、踩过的坑（别再踩）

1. **倍数参数直接用 0–100**：被当 80 倍速、超硬范围报错。用百分比展示层转换。
2. **记录截断不删文件**：旧音频变孤儿，outputs 长期累积。截断时连带删 + 路径校验。
3. **徽标独占一行导致卡片错位**：改固定高度占位行。
4. **改名后 reference_path 失效**：素材目录改名后同步改写路径。
5. **自动化逐字符输入与实时夹取冲突**：`bu.type` 逐字符触发 input、被 clamp 改写 value 导致错乱（曾产生 200/200）。验证时用 JS 直接设最终值再触发事件，关键操作后回读原始数据核对。
6. **select 不收缩静默溢出**：flex 子项默认 min-width:auto，给 select/input 加 `min-width:0`、`flex:1` 自适应。
7. **孤儿空目录阻塞改名**：materials 下历史残留空壳目录会让"目标目录已存在"，先排查无引用空目录、确认后清理。
8. **遗留（未修）**：`server.py` `do_POST` 内重复 `import threading`，使函数把 threading 当局部变量，`/api/shutdown` 访问 `threading.Timer` 报 UnboundLocalError、关闭按钮退不掉进程。重启需直接按监听 PID 结束。用户未要求处理，勿擅自展开。
